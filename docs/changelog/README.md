# Changelog

A record of milestones and decisions in building kpixel. Git history shows _what_ changed; these entries explain _why_, and where the project stands.

## Files

One file per entry, named `YYYY-MM-DD-<slug>.md`, where the date is the day the work landed and `<slug>` is a short kebab-case name (e.g. `2026-11-03-document-model.md`). Filenames sort chronologically, so the folder reads as a timeline.

## Template

```md
# <Title>

<One or two sentences: what landed and why it matters.>

## Changes

- <Notable change, with links to key files or docs>

## Decisions

- <Choice made and the reason, including alternatives rejected>

## Next

- <What this unblocks or what is still open>
```

Omit any section that would be empty. Keep entries short: a screen or less.
